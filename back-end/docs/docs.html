CC Order Tracking System — Backend

FastAPI backend for the Computer Clinic order tracking platform.

Overview

The backend for the Computer Clinic Order Tracking System provides a RESTful API for managing and tracking device repair orders. It supports two classes of consumers: Admin users who create, update, and close orders, and Customer users who view the status of their orders.

Built with FastAPI, the service connects to an Apache Cassandra database for durable, scalable storage. The API is automatically documented via OpenAPI at /docs and /redoc when the server is running.

Getting Started

Prerequisites

  • Python 3.14+
  • Docker & Docker Compose

Setup

  1. Start Cassandra 
    cd db
docker compose up -d
  2. Activate the virtual environment 
    source .venv/bin/activate
  3. Run the server 
    uvicorn main:app --reload --host 0.0.0.0 --port 8000

The API will be available at http://localhost:8000. Interactive docs at http://localhost:8000/docs.

Get all repairs for a specific order.

Update a specific repair within an order. If repair_status is set to "Finished", repair_finish is automatically set to the current timestamp.

Create a new order with one or more repair items. Generates UUIDs for order_id, repair_id (per item), and order_creation.

Add a single repair to an existing order. Validates that the order exists before inserting.

ParameterType

Business Logic

calculate_actual_hours(start, finish)

Computes the elapsed time between repair_start and repair_finish. Returns the difference in hours (rounded to 2 decimal places). Returns None if either timestamp is missing.

def calculate_actual_hours(start, finish):
    if not start or not finish:
        return None
    return round((finish - start).total_seconds() / 3600, 2)
enrich_row(row)

Takes a raw Cassandra row, converts it to a dict via _asdict(), and attaches the actual_hours key computed from calculate_actual_hours. Used in admin endpoints to provide additional context.

Architecture

Application Lifecycle

  1. Startup: FastAPI creates the app, registers CORS middleware, then the startup event connects to Cassandra and ensures the keyspace exists.
  2. Routing: All routes from routes.py are included via app.include_router(router).
  3. Shutdown: The shutdown event closes the Cassandra cluster connection.

CORS Middleware

Configured to allow requests from both frontend applications:

allow_origins = ["http://localhost:3000", "http://localhost:3001"]
allow_credentials = True
allow_methods = ["*"]
allow_headers = ["*"]

Database Connection

The CassandraManager class (in database.py) is a singleton that manages a single cluster connection. The session is provided to route handlers via a FastAPI dependency get_cassandra_session().

Security Notes

  • There is currently no authentication or authorization. Admin and Customer paths are separated by URL convention only.
  • CQL injection is mitigated via parameterized queries (%s placeholders).
  • No rate-limiting, request logging, or API key checks are in place.
